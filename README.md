# 🤖 Discord Shift Bot — مدیریت شیفت بازیکنان FiveM

ربات دیسکورد برای مدیریت شیفت بازیکنان سرور FiveM، نوشته‌شده با **Python** و **discord.py**.

بازیکنان با `/shift` شیفت خود را شروع و تمام می‌کنند. ربات با بررسی `players.json` سرور
FiveM مطمئن می‌شود بازیکن واقعاً آنلاین است، زمان‌ها را با دقت ثبت می‌کند، در صورت قطع شدن
بازیکن از سرور یک **Grace Period** (پیش‌فرض ۱۵ دقیقه) اعمال می‌کند و تمام اطلاعات را به‌صورت
پایدار در فایل JSON ذخیره می‌کند تا بعد از Restart ربات از بین نرود.

---

## 📁 ساختار پروژه

```
discord_shift_bot/
├── bot.py                  ← کل پروژه (کد + تنظیمات + توکن)
├── requirements.txt
├── data/
│   ├── shift_data.json     ← دیتابیس اصلی (خودکار ساخته می‌شود)
│   └── backups/            ← بک‌آپ خودکار
└── logs/
    └── bot.log             ← لاگ ربات (خودکار ساخته می‌شود)
```

> ℹ️ کل کد **و تنظیمات** در یک فایل (`bot.py`) قرار دارد. تنظیمات (توکن، کانال،
> نقش‌ها) در بخش «تنظیمات ربات» بالای فایل است و بخش‌های کد با کامنت‌های
> جداکننده مشخص شده‌اند: Time helpers، Database، FiveM، Permissions،
> Shift management، Statistics، Admin و Bot entry point.

نسخه **Python 3.10 یا بالاتر** نیاز است.

بررسی نصب:

```bash
python --version
```

## 4️⃣ ساخت Discord Bot

1. وارد [Discord Developer Portal](https://discord.com/developers/applications) شوید.
2. روی **New Application** کلیک کنید و یک نام انتخاب کنید.
3. از منوی سمت چپ به بخش **Bot** بروید و روی **Reset Token** کلیک کنید.
4. توکن تولیدشده را کپی کنید (این همان توکنی است که در `bot.py` قرار می‌گیرد).
5. از بخش **OAuth2 → URL Generator**:
   - در **Scopes** گزینه `bot` و `applications.commands` را تیک بزنید.
   - در **Bot Permissions** گزینه‌های `Send Messages`، `Embed Links`،
     `Use Slash Commands`، `Read Messages/View Channels` و `Manage Messages`
     (برای Edit کردن پیام شیفت) را انتخاب کنید.
6. لینک تولیدشده را در مرورگر باز کنید و ربات را به سرور خود اضافه کنید.

---

## 5️⃣ فعال‌کردن Intents لازم

در صفحه **Bot** در Developer Portal بخش **Privileged Gateway Intents** را باز کنید:

- ربات این پروژه فقط به `Intents.default()` نیاز دارد و هیچ Intent خاصی اجباری نیست.
- اگر در آینده خواستید از اعضای سرور (Members) استفاده کنید، گزینه
  **Server Members Intent** را نیز روشن کنید.

برای دستورات Slash لازم است ربات در سرور شما **Scope** مربوط به
`applications.commands` را داشته باشد (قدم ۴).

## 6️⃣ تنظیم توکن

توکن ربات **فقط در `bot.py`** و در بخش «تنظیمات ربات» (بالای فایل) قرار دارد:

```python
EMBEDDED_TOKEN = "توکن_واقعی_ربات"
```

برای تعویض توکن فقط همین یک مقدار را عوض کنید (فایل `.env` دیگر خوانده نمی‌شود).

> ⚠️ اگر `bot.py` را در جایی عمومی (مثل GitHub) قرار می‌دهید، Discord ممکن است
> توکن را باطل کند — در آن صورت توکن جدید از Developer Portal بگیرید.

## 7️⃣ تنظیم کانال و نقش‌ها (داخل `bot.py`)

همه تنظیمات در `bot.py` و در بخش «تنظیمات ربات» (بالای فایل) قرار دارند:

```python
CONFIG = {
    "guild_id": "",
    "channel_id": "شناسه_کانال_شیفت",
    "roles": {
        "shift": ["آیدی_نقش_شیفت"],
        "moderator": ["آیدی_نقش_مودراتور"],
        "manager": ["آیدی_نقش_منیجر"]
    },
    "settings": {
        "disconnect_grace_minutes": 15,
        "timezone": "Asia/Tehran",
        "players_url": "http://x.paradiserp.ir:30120/players.json",
        "check_interval_seconds": 10
    }
}
```

| تنظیم | توضیح |
|---|---|
| `guild_id` | (اختیاری) اگر پر شود، دستورات فقط روی همان سرور Sync می‌شوند (انتشار فوری). اگر خالی بماند، ربات هنگام بالا آمدن خودکار به **همه سرورهایی که در آن است** سینک می‌کند. |
| `channel_id` | تنها کانالی که دستورات در آن کار می‌کنند. |
| `roles.shift` | اجازه استفاده از `/shift` |
| `roles.moderator` | اجازه `/check` و `/list` (و `/shift`) |
| `roles.manager` | اجازه `/reset`، `/wipe`، `/wipeall` (و تمام دسترسی‌های مودراتور) |
| `disconnect_grace_minutes` | مدت مهلت بازگشت بازیکن بعد از قطعی (پیش‌فرض ۱۵) |
| `timezone` | منطقه زمانی نمایش ساعت‌ها (ذخیره‌سازی همیشه UTC است) |
| `players_url` | آدرس `players.json` سرور FiveM |
| `check_interval_seconds` | بازه بررسی آنلاین بودن بازیکنان (پیش‌فرض ۱۰) |

## 8️⃣ تنظیم Role IDها

برای پیدا کردن شناسه نقش‌ها در دیسکورد:

1. در تنظیمات دیسکورد، **Advanced → Developer Mode** را روشن کنید.
2. روی نقش موردنظر راست‌کلیک کنید → **Copy Role ID**.
3. شناسه را در آرایه مربوطه داخل `CONFIG` در `bot.py` قرار دهید.

> 🏷️ یک کاربر می‌تواند چند نقش داشته باشد؛ بالاترین سطح اعمال می‌شود
> (Manager > Moderator > Shift).

## 9️⃣ تنظیم Channel ID

1. روی کانال موردنظر راست‌کلیک کنید → **Copy Channel ID** (Developer Mode باید روشن باشد).
2. شناسه را در `channel_id` داخل `CONFIG` در `bot.py` قرار دهید.

تمام دستورات فقط در همین کانال کار می‌کنند؛ در کانال‌های دیگر پیام
«این دستور فقط در Channel مخصوص Shift قابل استفاده است» نمایش داده می‌شود.

## 1️⃣1️⃣ نحوه استفاده از `/shift`

1. کاربر `/shift` را در کانال مخصوص اجرا می‌کند.
2. **اولین بار:** اگر قبلاً ثبت نشده باشد، ربات یک فرم کوچک باز می‌کند و فقط
   **شناسه (ID) بازیکن** را می‌پرسد — همان عددی که در کنار `name` داخل `players.json`
   است (مثلاً `12`). ربات با آن ID بازیکن را در `players.json` پیدا می‌کند، خودش
   `name` و کلید شناسایی را استخراج و در دیتابیس ذخیره می‌کند:
   - اگر سرور `identifiers` بدهد → شناسه پایدار `license:` / `license2:` ذخیره می‌شود.
   - اگر `identifiers` خالی باشد (مثل سرورهای معمولی بدون کانکتور) → شناسایی بر اساس
     **نام داخل بازی** انجام می‌شود (`name:...` ذخیره می‌شود، بدون حساسیت به حروف بزرگ/کوچک).
   (شرط: بازیکن باید داخل بازی آنلاین باشد.)
   از بار دوم به بعد دیگر هیچ سوالی پرسیده نمی‌شود.
3. پنل **SHIFT MANAGEMENT** با دو دکمه نمایش داده می‌شود:
   - 🟢 **Start Shift** — فقط وقتی فعال است که شیفت فعالی وجود نداشته باشد.
   - 🔴 **End Shift** — فقط وقتی فعال است که شیفت فعال باشد.
4. **Start Shift:** ربات `players.json` را چک می‌کند؛ اگر بازیکن آنلاین نباشد، شیفت شروع
   نمی‌شود. اگر آنلاین باشد، زمان شروع (UTC) ثبت و پیام زیر در کانال ارسال می‌شود:

```
PlayerName (همان اسم داخل بازی که ثبت شده — بدون @)

On : 11:12
Off : --
```

5. **End Shift:** زمان پایان ثبت، مدت محاسبه و به Total اضافه می‌شود، سشن در JSON ذخیره
   و همان پیام بالا Edit می‌شود:

```
PlayerName

On : 11:12
Off : 23:59
```

> یک بازیکن هرگز نمی‌تواند دو شیفت همزمان داشته باشد و هیچ‌کس نمی‌تواند شیفت شخص دیگری
> را تمام کند.

### قطع شدن بازیکن از سرور (Grace Period)

اگر بازیکنی شیفت فعال داشته باشد و از FiveM خارج شود:

1. ربات **بلافاصله** شیفت را تمام نمی‌کند.
2. یک **Grace Period** (پیش‌فرض ۱۵ دقیقه) شروع می‌شود و ربات هر چند ثانیه چک می‌کند.
3. اگر بازیکن قبل از پایان مهلت برگردد → مهلت لغو و شیفت ادامه پیدا می‌کند.
4. اگر برنگردد → شیفت به‌صورت خودکار با زمان پایان
   `زمان قطعی + ۱۵ دقیقه` بسته می‌شود و پیام کانال به‌روزرسانی می‌شود.

## 1️⃣2️⃣ نحوه استفاده از `/check`

فقط برای **Moderator** و **Manager** (در کانال مخصوص):

```
/check user:@Player
```

خروجی شامل:

```
Shift Statistics

User: @Player

Status: OFF SHIFT

Total Shift:
42h 17m

Today:
5h 20m

This Week:
18h 42m

This Month:
40h 05m

Sessions:
17

Last Shift:
2026-08-10 23:15 → 2026-08-11 01:20
```

- «Today / This Week / This Month» بر اساس زمان پایان سشن‌ها و در **منطقه زمانی تنظیم‌شده**
  محاسبه می‌شود (هفته از دوشنبه شروع می‌شود).
- اگر شیفت فعال باشد، «Status» برابر `ON SHIFT` است.

فقط برای **Moderator** و **Manager**:

```

```

اگر تعداد بازیکنان زیاد باشد، با دکمه‌های ◀ ▶ صفحه‌بندی می‌شود (۱۰ نفر در هر صفحه).

## 1️⃣4️⃣ نحوه استفاده از `/reset`

فقط برای **Manager**:

1. `/reset` را در کانال مخصوص اجرا کنید.
2. یک پیام هشدار با دو دکمه نمایش داده می‌شود: **Confirm Reset** و **Cancel**.
3. با تأیید، تمام **زمان‌های شیفت، سشن‌ها و شیفت‌های فعال** پاک می‌شوند.
   ثبت‌نام بازیکنان (شناسه‌های FiveM) حفظ می‌شود تا مجبور به ثبت‌نام دوباره نباشند.
4. فقط شخصی که دستور را اجرا کرده می‌تواند تأیید کند.

---

## 1️⃣5️⃣ نحوه استفاده از `/wipe` و `/wipeall`

فقط برای **Manager**:

- **`/wipe user:@Player`** — بازیکن انتخاب‌شده را **به‌طور کامل** از دیتابیس حذف می‌کند
  (ثبت‌نام، کل زمان‌ها، سشن‌ها و شیفت فعال). برای حذف یک بازیکن خاص از سیستم.
- **`/wipeall`** — **تمام دیتابیس** (همه بازیکنان و همه اطلاعات شیفت) را با یک دکمه تأیید
  پاک می‌کند. با **Confirm Wipe All** اجرا می‌شود و فقط شخصی که دستور را زده می‌تواند
  تأیید کند.

> تفاوت با `/reset`: `/reset` فقط آمار شیفت را صفر می‌کند ولی ثبت‌نام بازیکنان را نگه
> می‌دارد؛ `/wipe` و `/wipeall` رکوردهای بازیکن را کاملاً از `shift_data.json` حذف می‌کنند.

## 1️⃣6️⃣ به‌روزرسانی دستورات Slash

وقتی کد ربات را عوض می‌کنید و دستور جدید اضافه می‌شود، فقط کافی است **ربات را Restart کنید** —
ربات هنگام بالا آمدن، دستورات را خودکار به همه سرورهایی که در آن است سینک می‌کند
(انتشار فوری، بدون نیاز به کار اضافه و بدون انتظار برای سینک سراسری دیسکورد).

---

## 👁️ نمایش دستورات در منوی Apps و تایپ `/`

دستورات Slash در منوی **Apps** و تایپ `/` از **یک‌سان** ثبت‌نام استفاده می‌کنند — چیزی جدا
برای منوی Apps وجود ندارد. اگر بعد از سینک موفق، دستورات در منوی Apps دیده نشد،
**کلاینت دیسکورد را کامل ببندید و دوباره باز کنید** (یا `Ctrl+R` بزنید) تا کش دستورات
رفرش شود.

## 🧠 منطق داخلی

- **شناسایی بازیکن:** `player.id` در FiveM یک شناسه موقت (Session) است و هرگز به‌عنوان
  شناسه دائمی استفاده نمی‌شود. ربات اول `license:` / `license2:` را ترجیح می‌دهد؛ اگر
  سرور `identifiers` خالی بدهد (در `players.json`)، به‌صورت خودکار به شناسایی بر اساس
  **نام داخل بازی** (`name:...`) برمی‌گردد. ساختار پاسخ می‌تواند لیست ساده یا
  `{"players": [...]}` / کلیدخورده با ID باشد — همه نرمال می‌شوند.
- **ذخیره‌سازی:** همه عملیات `load → validate → modify → save` با یک **قفل asyncio** انجام
  می‌شود و نوشتن به‌صورت **Atomic** است (فایل موقت → `os.replace`)، پس فایل JSON هیچ‌وقت
  خراب نمی‌شود. قبل از هر نوشتن، نسخه قبلی در `data/backups/` ذخیره می‌شود
  (۲۰ نسخه اخیر نگه داشته می‌شود).
- **فایل خراب:** اگر JSON خراب باشد، فایل به‌جای پاک شدن کنار گذاشته می‌شود
  (`shift_data_corrupt_...json`) و ربات با داده خالی شروع می‌کند.
- **زمان:** همه زمان‌ها به‌صورت UTC (با Offset) ذخیره و فقط هنگام نمایش به منطقه زمانی
  تنظیم‌شده تبدیل می‌شوند. مدت شیفت از تفاضل دو Timestamp آگاه به منطقه زمانی محاسبه می‌شود.
- **خطاها:** قطعی FiveM، Timeout، JSON نامعتبر، خطای Discord API، نقش/کانال ناموجود و
  Rate Limit باعث Crash نمی‌شوند؛ همگی لاگ می‌شوند و به کاربر پیام مناسب داده می‌شود.
